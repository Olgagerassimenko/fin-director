# Автообновление отчёта «Согласованные оплаты» (Битрикс)

Отчёт `bitrix_отчёт_оплаты.html` собирается из данных заявок на оплату, которые в Битриксе
идут через бизнес-процессы «Живой ленты» (шаблон «ФЗ | Платежи»). REST/вебхук их не отдаёт
(bizproc = insufficient_scope), поэтому данные берём со страницы **Мои процессы** в браузере
пользователя (он там залогинен).

## Файлы (в репо, папка `оплаты_pipeline/`)
- `gen_oplaty.py` — генератор: из данных (≡-формат) + шаблона делает отчёт.
- `оплаты_шаблон.html` — шаблон отчёта (вся аналитика считается на лету из блока `#raw`).
- `oplaty_data.txt` — накопленные данные, строки:
  `Дата≡Тип платежа≡Заявитель≡Город≡Сумма≡Статус≡Комментарий≡Файл`
  (город/сумма/файл часто пустые — это норма).

## Процедура обновления (что делать сессии по расписанию)
1. Склонировать репо: `git clone --depth 1 https://github.com/Olgagerassimenko/fin-director.git`,
   взять `оплаты_pipeline/{gen_oplaty.py, оплаты_шаблон.html, oplaty_data.txt}`.
2. Через браузер пользователя (Claude-in-Chrome) открыть
   `https://segodnya.bitrix24.kz/bizproc/userprocesses/` и `...?PAGEN_1=2&page=page-2` (и page-3 при
   необходимости), снять текст (`get_page_text`).
3. Распарсить строки заявок (пропускать строки «ФЗ | Платежи #…» — это родительский процесс):
   - Дата = «Активность» (напр. «12 августа» → `12.08`).
   - Тип = из «Тип платежа: …».
   - Заявитель = из заголовка «…от ИМЯ».
   - Статус = `Завершён`, если «ЗАВЕРШЕН», иначе `В работе`.
   - Комментарий = из «Описание: …» (можно с усечением).
4. Найти самую свежую дату в `oplaty_data.txt`; добавить только заявки НОВЕЕ неё
   (дедуп по Заявитель+Дата+Комментарий). Новые — сверху.
5. `python3 gen_oplaty.py oplaty_data.txt bitrix_отчёт_оплаты.html`.
6. Опубликовать `bitrix_отчёт_оплаты.html` в корень репо через веб-GitHub
   (`/upload/main`, Commit). Туда же обновлённый `оплаты_pipeline/oplaty_data.txt`.
7. Проверить живую ссылку:
   `https://lucky-river-eaf1.findirfoodzavod.workers.dev/bitrix_отчёт_оплаты.html`

## Важно / ограничения
- Нужен включённый компьютер пользователя и вход в Битрикс — иначе собрать данные нельзя,
  тогда просто пропустить прогон и не трогать отчёт.
- Суммы/город спрятаны под «…ещё» (по каждой заявке), массово не берём — в отчёте это
  «Сумма (где указана)», что нормально.
- По-настоящему надёжное автообновление без браузера — только если оплаты завести
  в CRM-смарт-процесс (см. «Битрикс — авто-оплаты — инструкция для админа.md»).
